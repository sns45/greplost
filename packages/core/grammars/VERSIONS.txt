Three departures from the pinned list in section 0.5 of
docs/superpowers/specs/2026-09-04-languages-iac-signals-design.md, all forced, all recorded
here with the reason (rulings, leaf 2.0 and leaf 2.6, 2026-09-04):

  yaml   The pinned tree-sitter-yaml 0.5.0 (ikatyang) carries a C++ external scanner
         (src/scanner.cc). `tree-sitter build --wasm` cannot link a C++ scanner: it fails with
         "This external scanner uses a symbol that isn't available to Wasm parsers" and leaves
         behind a wasm whose scanner entry points are undefined, so web-tree-sitter refuses to
         load it ("bad export type for 'tree_sitter_yaml_external_scanner_create': undefined").
         The maintained successor under the tree-sitter-grammars org has a C scanner and ships
         a prebuilt wasm, so it is pinned at 0.7.1 and copied.

  rust   tree-sitter-rust 0.24.0's prebuilt wasm was generated from an older parser than the
         src/parser.c in the same tarball: the wasm reports ABI 14 while src/parser.c declares
         LANGUAGE_VERSION 15. Building from the tarball's own sources yields ABI 15, so the
         vendored artifact provably matches the pinned grammar. python and java were checked
         the same way and their shipped wasm agrees with their sources, so those are copied.

  kotlin The pinned tree-sitter-kotlin **0.3.8 release** predates Kotlin 1.4's `fun interface`
         and does not parse it. On the pinned corpus (kotlinx.coroutines, 163 files) 0.3.8 left
         a root-level ERROR node in 7 files (4.3%), five of them on a `fun interface`, against
         the 1% parse-health bound leaf 2.6 is gated on. The same repository's main branch has
         fixed it (`choice("class", seq(optional("fun"), "interface"))`) and has not been
         released, so the vendored artifact is built from a pinned commit of main rather than
         from the tag: 0 of 163 files carry a root-level ERROR with it, and its node names are
         0.3.8's, so `extract/kotlin.ts` reads the same tree either way (one addition: main
         wraps an extension receiver in a `receiver_type` node).

         One defect of the vendored grammar, measured and pinned by a test in
         packages/core/test/extract-kotlin.test.ts: a one-line **object** body
         (`object A { fun b() {} }`) parses as an expression - an object literal applied to a
         lambda - so the file yields no declaration, and because there is no ERROR node
         `findUnparsableFiles` does not report it either. A one-line *class* body is read
         correctly, and both are fine written over two lines, which is how Kotlin is written.
         The pinned corpus has no instance.

         The alternative considered and rejected: `@tree-sitter-grammars/tree-sitter-kotlin`
         1.1.0, the fork under the tree-sitter-grammars org, which ships a wasm and parses
         `fun interface` but leaves 2 of the 163 files with a root-level ERROR, silently
         mis-parses an annotated `annotation class` as an expression (and a one-line class body,
         which the vendored grammar reads), and renames every node
         (`identifier` for both `simple_identifier` and `type_identifier`, `import` for
         `import_header`). Recorded so the choice is not made again by coin flip (ruling,
         leaf 2.6).

Vendored so installs never need a C++ toolchain.
Regenerate the three that ship a usable wasm with: bun scripts/vendor-grammars.ts <node_modules>
Rebuild the four that are built from source with:  bash scripts/build-grammars.sh
