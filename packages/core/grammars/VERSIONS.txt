Two departures from the pinned list in section 0.5 of
docs/superpowers/specs/2026-09-04-languages-iac-signals-design.md, both forced, both recorded
here with the reason (ruling, leaf 2.0, 2026-09-04):

  yaml   The pinned tree-sitter-yaml 0.5.0 (ikatyang) carries a C++ external scanner
         (src/scanner.cc). `tree-sitter build --wasm` cannot link a C++ scanner: it fails with
         "This external scanner uses a symbol that isn't available to Wasm parsers" and leaves
         behind a wasm whose scanner entry points are undefined, so web-tree-sitter refuses to
         load it ("bad export type for 'tree_sitter_yaml_external_scanner_create': undefined").
         The maintained successor under the tree-sitter-grammars org has a C scanner and ships
         a prebuilt wasm, so it is pinned at 0.7.1 and copied.

  rust   tree-sitter-rust 0.24.0's prebuilt wasm was generated from an older parser than the
         src/parser.c in the same tarball: the wasm reports ABI 14 while src/parser.c declares
         LANGUAGE_VERSION 15. Building from the tarball's own sources yields ABI 15, so the
         vendored artifact provably matches the pinned grammar. python and java were checked
         the same way and their shipped wasm agrees with their sources, so those are copied.

Vendored so installs never need a C++ toolchain.
Regenerate the three that ship a usable wasm with: bun scripts/vendor-grammars.ts <node_modules>
Rebuild the four that are built from source with:  bash scripts/build-grammars.sh
